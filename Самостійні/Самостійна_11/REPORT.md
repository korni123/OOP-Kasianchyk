# Звіт до самостійної роботи №11

## Опис пайплайнів

### 1. Найпопулярніші продукти за категоріями

`GroupBy` (за продуктом) → `Select` (сума кількості) → `Join` (назва і категорія продукту) → `GroupBy` (за категорією) → `OrderByDescending` + `Take(3)`.

Спочатку групуємо продажі, а потім з'єднуємо з продуктами — так `Join` працює з меншою кількістю записів.

### 2. Загальний дохід за містами клієнтів

`Join` (ціна з продуктів) → `Join` (місто з клієнтів) → `GroupBy` (за містом) → `Sum` (дохід) → `OrderByDescending`.

Два `Join` потрібні, бо ціна зберігається в продуктах, а місто — у клієнтах.

### 3. Продажі за місяцями та роками

`Join` (ціна) → `GroupBy` за роком і місяцем → `Sum` (кількість і дохід) → `OrderBy` (рік) → `ThenBy` (місяць).

### 4. Власний: топ-5 клієнтів за витратами та їхня улюблена категорія

`Join` → `GroupBy` (за клієнтом) → `Sum`, `Count`, вкладений `GroupBy` + `Aggregate` (улюблена категорія) → `Join` (ім'я клієнта) → `OrderByDescending` → `Take(5)`.

`Aggregate` знаходить категорію з найбільшою кількістю покупок за один прохід.

## Аналіз

- **Перший запуск набагато повільніший** — у цей момент .NET компілює код методів і LINQ-операторів (JIT). Найповільніший перший пайплайн, бо він запускається першим.
- **Після прогріву** найдовше виконується пайплайн 4 — у ньому найбільше операцій (два `Join`, вкладене групування, `Aggregate`).
- `Join` у LINQ працює через хеш-таблицю, тому він швидкий навіть на великій кількості записів.
- На час також впливають збирання сміття (GC) та інші програми на комп'ютері.

## Висновки

- LINQ зручний для ETL та аналітики: запит читається зверху вниз і схожий на SQL (`JOIN`, `GROUP BY`, `ORDER BY`), без вкладених циклів.
- На сотнях записів пайплайни виконуються за частки мілісекунди — продуктивності вистачає.
- Щоб виміряти час правильно, результат треба матеріалізувати через `ToList()`, бо LINQ виконується відкладено.
- Для швидкості краще групувати і фільтрувати дані якомога раніше.
- Щоб код залишався читабельним, кожен пайплайн винесено в окремий метод з зрозумілою назвою.
